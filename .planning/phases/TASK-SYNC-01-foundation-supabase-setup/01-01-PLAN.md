<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> Supabase API | Untrusted browser requests are authenticated via Supabase Auth and restricted by RLS. |
| Server Actions -> Supabase | Server-side operations use the user's session token to maintain trust context. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|-----------|-----------|-------------|-----------------|
| T-01-01 | Elevation of Privilege | tasks table | mitigate | Enforce Row Level Security (RLS) to ensure users can only access their own data. |
| T-01-02 | Information Disclosure | Supabase Keys | mitigate | Use 'NEXT_PUBLIC_' prefix only for the 'anon' key; keep 'service_role' key out of frontend code. |
| T-01-SC | Tampering | npm installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED] packages (supabase, zod). |
</threat_model>
